## Overview
Cisalpine Engine is a GPU-driven 2D falling sand simulation built with OpenGL 4.6 compute shaders. Every aspect of the simulation, including physics, element interactions, lighting, and rendering, runs entirely on the GPU. This enables large interactive worlds at real-time framerates.

Elements are defined in a data-driven JSON registry, and complex behaviors are authored using a custom domain-specific language (DSL) that compiles directly to GLSL at load time. The engine features a full radiance cascade global illumination system, a chunk-based sleep/wake optimization layer, and a force field physics model supporting effectors like black holes, explosions, and directional fans.

## Features

- **Fully GPU-Driven Simulation** — All particle physics, movement, and element interactions execute in OpenGL 4.6 compute shaders. Double-buffered state textures (`RGBA8UI`) encode element ID, lifetime, flags, and custom data per pixel.
 
- **Data-Driven Element Registry** — Elements are defined in `elements.json` with properties like type (Static, Granular, Liquid, Gas), density, viscosity, color, opacity, and rendering hints. Element `#define` constants are auto-generated and injected into shaders at compile time.
 
- **Custom Behavior DSL** — A purpose-built scripting language lets you define element interactions without touching GLSL directly. The DSL supports commands like `INTERACT`, `ROLL`, `TURN`, `CREATE`, `BURN`, `SWARM`, `EXPLODE`, and conditional logic with `IF`/`AND`. Scripts compile to GLSL and are injected into the simulation shader via a marker-based injection system. User-defined variables are bit-packed into a 32-bit `customData` field per pixel.
 
- **Radiance Cascade Global Illumination** — A multi-level radiance cascade system replaces traditional bounce lighting. Emissive elements are extracted into a radiance field G-buffer, cascades merge from coarse to fine, and the result resolves to a per-pixel lightmap. Configurable cascade levels, sky-aware ambient, and day/night cycling are supported.
 
- **Chunk-Based Sleep System** — The world is divided into 32×32 chunks that can sleep when inactive. An indirect dispatch system builds a list of active chunks on the GPU each frame, so only chunks with activity are simulated. Periodic wake intervals ensure slow reactions (like grass spreading) still fire in sleeping regions.
 
- **Force Field Physics** — A double-buffered `RGBA16F` force field texture drives wind, gravity modulation, and effector-based forces. Effectors (black holes, bombs, fans) are written into an SSBO by the simulation shader and consumed by the physics shader on the next frame.
 
- **Per-Pixel Rendering Pipeline** — A multi-pass compute pipeline generates color, normals, sky, and lightmap textures, then composites them into a final display image. Elements support glow, gemstone refraction, specular highlights, transmission tinting, heightmap-based normals, and animated color effects (fire flicker, liquid shimmer, rainbow cycling, void distortion).
 
- **Interactive Wind Tool** — A drag-based wind brush applies directional forces to the force field, letting you push particles around in real time.
 
- **Save/Load System** — World state serializes to `.csav` files using RLE-compressed RGBA pixel data. Native file dialogs are supported on Windows, Linux (zenity/kdialog), and macOS (osascript).
 
- **Debug Overlay** — A tilde-toggled overlay shows GPU pass timings, chunk activity maps, render buffer visualization (color, normals, lightmap, state, sky, force field, radiance field), and hardware info.
 
- **ImGui Interface** — A themed sidebar provides element selection (tabbed and searchable), brush controls (circle, square, star shapes), lighting/sky settings, simulation speed, and camera controls with smooth zoom and pan.

## Architecture
 (Note: Am lazy. This section was generated by an LLM but has been vetted for accuracy)
 
The engine is structured around a small set of core C++ classes and a bank of GLSL compute shaders.
 
### C++ Layer
 
| File | Role |
|---|---|
| `main.cpp` | Entry point — initializes and runs the `App`. |
| `app.cpp/hpp` | Window management, input handling, ImGui UI, brush dispatch, camera, save/load. |
| `world.cpp/hpp` | Owns all GPU resources (textures, SSBOs, shaders). Runs the simulation loop, rendering pipeline, and radiance cascade passes. |
| `registry.cpp/hpp` | Loads `elements.json`, populates the `GPUElementData` SSBO, generates shader `#define` headers, and drives DSL compilation. |
| `compiler.cpp/hpp` | Lexer, parser, and GLSL code generator for the custom DSL. Tokenizes scripts, builds an AST, allocates bit-packed variables, and emits a `switch/case` dispatch function injected into the simulation shader. |
| `shader.cpp/hpp` | Thin OpenGL shader wrapper — compiles vertex/fragment and compute programs, handles header injection and DSL marker replacement. |
 
### GPU Pipeline (per frame)
 
1. **Force Update** (`physics.comp`) — Reads the effector list SSBO and current force field, diffuses and applies effector forces (black holes, bombs, fans), writes the next force field.
2. **Simulation** (`simulation.comp`) — Reads current state + force field, executes element physics (gravity, density sorting, viscosity, gas rise), runs DSL-generated custom behaviors, writes new effectors, outputs next state. Dispatched indirectly over active chunks when chunk sleep is enabled.
3. **Render** (`render.comp`) — Converts state texture to color, normal, and sky textures. Applies animated color effects and heightmap-based normal generation.
4. **Radiance Cascades** — Three sub-passes:
   - `rc_emitters.comp` — Extracts emission and opacity into a radiance field G-buffer.
   - `rc_cascade.comp` — Merges cascade levels from coarse to fine via ray marching through the radiance field.
   - `rc_resolve.comp` — Bilinearly interpolates cascade level 0 probes to produce a per-pixel lightmap.
5. **Composite** (`composite.comp`) — Combines color, normals, lightmap, and sky into the final display texture with ambient, specular, and glow.
6. **Quad Blit** (`quad.vert/frag`) — Renders the display texture to screen with camera zoom/pan UV remapping.
 
### DSL Compilation Flow
 
```
elements.json "script" field
        │
        ▼
   Lexer (tokenize)
        │
        ▼
   Parser (AST: DefineNode, InteractNode, RollNode, TurnNode, ...)
        │
        ▼
   Bit-pack allocator (DEFINE'd variables → 32-bit customData)
        │
        ▼
   GLSL emitter (switch/case per element, bit-mask read/write ops)
        │
        ▼
   Injected at "// DSL_INJECTION_POINT" marker in simulation.comp
```

## Build Instructions
 
### Prerequisites
 
- **C++17** compiler (GCC 10+, Clang 12+, or MSVC 2019+)
- **CMake** 3.16+
- **OpenGL 4.6** capable GPU and drivers
- **GLFW 3**
- **GLAD** (OpenGL 4.6 Core loader)
- **GLM**
- **Dear ImGui** (with GLFW + OpenGL3 backends)
- **nlohmann/json** (ordered_json)
- **stb_image**
 
### Building
 
```bash
git clone https://github.com/your-username/cisalpine-engine.git
cd cisalpine-engine
git submodule update --init --recursive
mkdir build && cd build
cmake ..
cmake --build . --config Release
```
 
### Running
 
The executable expects `data/elements.json`, `data/fonts/`, and `shaders/` directories relative to the working directory.
 
```bash
./cisalpine
```

## Performance

The engine is designed to keep the CPU nearly idle while the GPU handles all heavy lifting. Typical performance characteristics on a mid-range discrete GPU (e.g., GTX 1660 / RX 5600):
 
- **600×600 world** at 60 FPS with 4 simulation steps per frame.
- **Chunk sleep** reduces simulation dispatch to only active regions. A mostly-static world with localized activity may run only 5–15% of chunks per frame.
- **Radiance cascades** with 5 levels typically cost under 1 ms total (emitter extraction + cascade merge + resolve).
- **GPU pass timings** are exposed in the debug overlay via hardware timer queries, broken down per pass (simulation, force update, chunk build, render, RC emitters, RC cascade, RC resolve, composite, quad blit).
